# Fordring 产品需求文档

## 1. 产品概述

Fordring 是一个 Arthas 集中管理平台，用于帮助研发人员统一管理需要接入 Arthas 的 Java 服务，将 Arthas 挂载到物理机或 Docker 容器中的 Java 进程，并通过 Web 控制台执行诊断命令，同时保留命令执行历史，便于审计与复用。

产品全称：`Tirion Fordring`

当前原型覆盖范围：

- 物理机 Java 进程与 Docker 容器 Java 进程的接入管理。
- 带接入前检查、Telnet/HTTP 端口配置的 Arthas 接入流程。
- 面向已接入目标的 Web 控制台命令执行能力。
- 命令历史、命令详情、再次执行、保存命令等命令管理能力。

## 2. 产品目标

- 提供统一入口管理需要接入 Arthas 的环境与目标实例。
- 降低生产诊断过程中手工 SSH、临时 attach 的操作成本。
- 让常用 Arthas 命令更容易执行、沉淀和复用。
- 保留命令、输出、耗时、状态、来源、执行人等信息，满足审计需要。
- 通过目标状态检查、命令超时和后续权限控制，降低误操作风险。

## 3. 用户与角色

### 管理员

- 维护接入目标。
- 执行 Arthas 接入与断开操作。
- 执行 Arthas 命令。
- 查看所有命令历史。
- 保存可复用命令。

### 研发人员

- 进入已接入目标的控制台。
- 执行快捷命令或手工输入 Arthas 命令。
- 查看自己的命令历史。
- 再次执行或保存有价值的命令。

后续权限设计应区分生产环境与非生产环境的访问范围和操作权限。

## 4. 信息架构

主导航：

- 接入管理
- 控制台
- 命令历史

全局界面：

- 左侧侧边栏展示产品名、菜单、当前激活页面和当前登录用户。
- 主内容区展示页面标题、页面说明和核心操作区。
- 接入确认、新增接入、再次执行、保存命令使用弹窗承载。
- 表格支持搜索、筛选、分页和行内操作。

## 5. 核心流程

### 5.1 新增接入目标

1. 用户进入「接入管理」页面。
2. 用户点击「新增接入」。
3. 系统打开「新增接入」弹窗。
4. 用户填写必填字段：
   - 接入名称
   - 主机地址
   - SSH 端口，默认 22；目标主机使用非默认 SSH 端口时可修改
   - 认证方式
   - 用户名
   - 目标类型：物理机 Java 或 Docker 容器
   - 容器名称：目标类型为 Docker 容器时必填
   - Java 进程 PID；可点击「获取 PID」从目标环境自动发现，发现失败时允许手动填写
5. 用户点击「保存并检测」。
6. 系统保存接入目标，并执行连通性与进程检测。
7. 目标出现在接入列表中，并展示状态：
   - 未接入
   - 已接入
   - 检查失败

### 5.2 接入 Arthas

1. 用户在未接入目标上点击「接入 Arthas」。
2. 系统打开「接入 Arthas」确认弹窗。
3. 弹窗展示目标摘要：
   - 环境或接入名称
   - 主机
   - 容器或目标名称
   - Java 进程 PID
4. 系统展示接入前检查结果：
   - Docker 可连接
   - 已发现 Java 进程
   - 当前用户具备 attach 权限
5. 用户配置 Telnet 端口与 HTTP 端口。
6. 用户点击「开始接入」。
7. 系统在目标实例上启动 Arthas。
8. 接入成功后，目标状态变为「已接入」，行内操作变为「进入控制台」和「断开」。
9. 接入失败后，目标状态变为「检查失败」或「接入失败」，用户可查看失败原因。

### 5.3 在控制台执行命令

1. 用户从已接入目标进入「控制台」。
2. 系统展示目标摘要：
   - 接入名称
   - 环境
   - 主机
   - 目标类型
   - 目标名称
   - PID
   - 状态
3. 用户选择快捷命令，或在输入框手动输入 Arthas 命令。
4. 用户点击「执行」。
5. 系统将命令发送到 Arthas，并将输出流式展示到终端面板。
6. 用户可以清空或复制终端输出。
7. 系统记录命令历史，包括命令、目标、执行时间、状态、耗时、来源、执行人和输出。

### 5.4 查看命令历史

1. 用户进入「命令历史」页面。
2. 用户按关键词、目标/环境、状态、日期范围筛选。
3. 系统展示分页后的命令执行记录。
4. 用户可以查看详情、再次执行或保存命令。
5. 详情区域展示命令元信息与执行输出。

### 5.5 再次执行命令

1. 用户从历史列表或详情中点击「再次执行」。
2. 系统打开「再次执行命令」弹窗。
3. 用户确认或切换目标。
4. 用户按需编辑命令内容。
5. 用户配置高级选项：
   - 超时时间，单位为秒
   - 执行后是否保留到历史
6. 用户点击「执行」。
7. 系统执行命令，并在开启保留历史时记录执行结果。

### 5.6 保存命令

1. 用户点击某条命令的「保存」。
2. 系统打开「保存命令」弹窗。
3. 用户填写：
   - 命令名称
   - 命令
   - 描述
   - 是否在控制台快捷显示
4. 用户点击「保存」。
5. 命令成为可复用命令；若开启快捷显示，则出现在控制台快捷命令区域。

## 8. 状态定义

### 接入目标状态

- 未接入：目标已创建，但 Arthas 未运行或未连接。
- 已接入：Arthas 已接入，可以在控制台执行命令。
- 检查失败：接入前检查失败。
- 接入失败：接入前检查通过，但 attach 操作失败。
- 已断开：Arthas 已被断开或连接已关闭。

### 命令状态

- 成功：命令执行完成且结果正常。
- 失败：命令返回错误或执行失败。
- 超时：命令超过配置的超时时间。
- 已取消：用户或系统取消了本次执行。

## 9. 非功能需求

- 命令输出应低延迟流式展示。
- 命令执行必须具备超时保护。
- 长输出应能被保存，不应阻塞页面交互。
- 接入与命令执行操作必须可审计。
- 敏感连接信息不得明文展示。
- 生产环境应支持更严格的权限与确认策略。
- 当存在数百个目标、数千条历史记录时，表格仍应保持可用。

## 10. 安全与审计需求

- 接入、断开、命令执行、再次执行、保存命令等操作必须记录审计日志。
- 高风险 Arthas 命令后续应支持黑名单或二次确认规则。
- 用户只能看到自己有权限访问的目标。
- 密码、令牌、私钥等凭据必须加密存储。
- 命令输出可能包含敏感数据，应遵循工作空间的数据留存策略。

## 11. 验收标准

- 用户可以新增 Docker 容器目标，并在接入管理列表中看到该目标。
- 用户可以执行接入前检查，并使用可配置端口接入 Arthas。
- 已接入目标可以打开控制台。
- 用户可以执行快捷命令和手动输入的命令。
- 控制台输出可见，并支持复制或清空。
- 每次命令执行都能出现在命令历史中。
- 用户可以筛选命令历史并查看命令详情。
- 用户可以带超时选项再次执行命令。
- 用户可以保存命令，并按需将其展示为快捷命令。
- 接入失败和命令执行失败时，应展示有帮助的失败信息。
